# 模型适配方式详解

> 本文说明如何把不同形态的模型接进 vLLM-Kestrel 引擎。适配的**统一原则**：部署/运行时
> 格式必须是引擎自有 VQF，不引入 ONNX / `.rknn` / torch 运行时；「适配」= 写解析器把
> 官方权重直接读成 VQF，而不是调库。

---

## 0. 适配分类总览

引擎按模型形态分成两类链路，**能否只靠 `vqf_conv` 一键接入，取决于模型是否是 Qwen 系
因果解码器**：

| 类别 | 代表模型 | 适配链路 | 是否需要改引擎代码 |
|---|---|---|---|
| Dense LLM | Qwen2.5-0.5B、Qwen3-0.6B | `vqf_conv` 转换 | 否（config 自动识别） |
| MoE LLM | Qwen3-30B-A3B | `vqf_conv` 转换 | 否 |
| 多模态 VL | Qwen3-VL-2B | `vqf_conv` 转换 | 否（vision 段自动识别） |
| Embedding | Qwen3-Embedding-0.6B | `vqf_conv` 转换 + 取值钩子 | 引擎已有，仅加参数 |
| 非自回归决策 | Laya（ModernBERT） | `laya_pack.py` + 独立前向 | 是（`vllm_laya.c`） |
| 目标检测 | YOLO v5/v8/v11 | `yolo_to_vqf.py` + 独立前向 | 是（`vllm_yolo.c`） |

前四类是**同一条因果解码器链路**，差异全部由 `config.json` 自动识别；后两类形态迥异，
各自走了独立的前向与权重打包路径。

## 1. 通用链路：Qwen 系 LLM（vqf_conv）

`vqf_convert/`（产物 `vqf_conv`）是唯一入口，输入 HF 模型目录，输出 `model.vqf`。
引擎侧 `vllm_safetensors.c`（转换器里对应 `model_cfgio.c`）负责解析 config 与 safetensors。

### 1.1 架构自动识别（`st_parse_config`）

引擎从 `config.json` 读取以下字段并据此分支，**无需手工声明架构**：

| config.json 字段 | 作用 | 触发分支 |
|---|---|---|
| `hidden_size` / `num_hidden_layers` / `num_attention_heads` / `num_key_value_heads` | 主干几何 | 基础 |
| `head_dim` | **显式优先**，缺省回退 `dim/heads`（Qwen3-0.6B 的 `dim/heads=64` 是错的，必须读显式 `head_dim=128`） | head_dim |
| `intermediate_size` | 稠密 FFN 中间维 | dense |
| `num_experts` + `moe_intermediate_size` + `num_experts_per_tok` | **三者均 >0 才判 MoE** | MoE |
| `vision_config` 子对象 + `vision_start_token_id` | 视觉编码器几何 | 多模态 |
| `mrope_section` / `deepstack_visual_indexes` | MRoPE / DeepStack 层索引 | 多模态 |
| `q_norm` / `mrope`（字符串子串 + 张量名） | Qwen3 的 q/k norm、MRoPE | Qwen3 特性 |
| `rms_norm_eps` | RMSNorm ε | 归一化 |

### 1.2 权重命名归一化（`strip_wrap`）

HF 导出有两种命名：

- 带包裹层：`model.language_model.layers.N.self_attn.q_proj.weight`（Qwen3-VL）
- 裸名：`model.layers.N.self_attn.q_proj.weight` 或 `layers.N.*`（Qwen2.5 / Qwen3-Embedding）

转换器用 `strip_wrap()` 把两侧的 `model.` / `model.language_model.` 前缀统一剥掉后比较，
使两套命名等价；同时 `st_load_layer_weights` 里对 `q/k/v/o_proj` 做了「先 `language_model`
后 `model.`」的顺序回退。**接入新模型时只需保证张量名符合其中一种，不必改引擎。**

### 1.3 词表准备

词表文件是**每个模型目录一份**，共三步：

```bash
# 1) vocab.bin（必需）：把 tokenizer.json 的 repr 域转成「引擎词表域」
python tools/build/build_vocab_bin.py <tokenizer.json> <旧vocab.bin> <out.vocab.bin>

# 2) merges.bin（可选但强烈建议）：byte-level BPE 合并表，缺失回退贪心最长前缀
python tools/gen_merges_bin.py <tokenizer.json> <out.merges.bin>

# 3) 放在模型目录下，命名固定为 vocab.bin / merges.bin
```

> **引擎词表域**：`vocab.bin` 存的是**原始字节**，仅把 `<=0x20` 的字节按 GPT-2
> `bytes_to_unicode` 转义（空格→`Ġ`=C4 A0、换行→`Ċ`=C4 8A），其余字节（含 CJK）原样。
> 这与标准 GPT-2 repr 域（所有字节都映射）**不同**，是接 Qwen 系最容易被忽视的坑。

### 1.4 转换与运行

```bash
# 转换
vqf_conv --model <hf_dir> --convert-vqf <out>/model.vqf --wmode dual
# 大模型（30B）低峰值内存转换
vqf_conv --model <hf_dir> --convert-vqf <out>/model.vqf --wmode dual --stream

# 运行
./vllm_kestrel --serve --port 8080 --model <out> --threads 8
```

## 2. Dense LLM：Qwen2.5 / Qwen3

形态：RMSNorm + GQA + SwiGLU + 因果注意力，`Qwen2ForCausalLM` / `Qwen3ForCausalLM`。

**Qwen2 vs Qwen3 的唯一加载差异**：

| 项 | Qwen2 系 | Qwen3 系 |
|---|---|---|
| q/k/v 投影 bias | 有（`self_attn.q_proj.bias` 等） | 无 |
| q_norm / k_norm | 无 | 有（`self_attn.q_norm.weight` 等） |

转换器 `qkv_bias_present()` 通过探测 `model.layers.0.self_attn.q_proj.bias` 是否存在来
决定是否分配 bias 张量；`cfg->has_q_norm` 决定是否加载 q_norm/k_norm。两条分支互斥，
**接 Qwen2.5 或 Qwen3 都不需要改代码**。

典型命令：

```bash
vqf_conv --model Qwen2.5-0.5B --convert-vqf qwen2.5-0.5b/model.vqf --wmode dual
```

## 3. MoE：Qwen3-30B-A3B

形态：`Qwen3MoeForCausalLM`，稀疏专家 FFN。

**识别**：`config.json` 里 `num_experts > 0 && moe_intermediate_size > 0 &&
num_experts_per_tok > 0` 三者同时成立时判 MoE，并把 `ffn_dim` 改写为
`n_experts * moe_ffn`（专家行连续堆叠后与稠密 FFN 同构）。

**权重差异点**：

- **专家权重**：`mlp.experts.{e}.gate_proj/up_proj/down_proj.weight`（每专家一份），
  由 `load_moe_experts_rowband()` / `load_moe_experts_down()` 把 N 个专家堆叠成连续
  行/列段（gate/up 按行堆叠 `[n_experts*moe_ffn, dim]`，down 按列散开 `[dim, n_experts*moe_ffn]`）。
- **router**：`mlp.gate.weight [n_experts, dim]` 保持 **f32 常驻**（top-k 选路边界精度敏感，
  不量化）。
- **分片**：30B 模型通常无单文件，是 `model-N-of-N.safetensors` 分片集（18867 个张量），
  由 `glob_model_shards()` 自动按序号排序加载；`MAX_TENSORS` 已扩到 65536。

典型命令：

```bash
vqf_conv --model Qwen3-30B-A3B --convert-vqf qwen3-30b-a3b/model.vqf --wmode dual --stream
```

## 4. 多模态：Qwen3-VL-2B

形态：`Qwen3VLForConditionalGeneration` = 语言主干（Qwen3）+ 视觉编码器（ViT）+
merger / DeepStack 桥接。

**识别**：`config.json` 存在 `vision_config` 子对象 → 解析 `depth / hidden_size / num_heads /
intermediate_size / patch_size / temporal_patch_size / spatial_merge_size / out_hidden_size /
in_channels / num_position_embeddings`，并读 `deepstack_visual_indexes` 数组与 MRoPE `mrope_section`。

**权重命名**：语言部分带 `model.language_model.layers.N.*` 包裹层（`strip_wrap` 兼容裸名），
视觉部分张量走 `st_vision_weights_alloc()` / `st_vision_load_weights()` 独立加载。

**转换**：`vqf_conv` 会**自动检测 vision 段**——加载成功则写出 `VQF_FLAG_VISION` 与整套
`v_q8_*` / `v_*` 张量；加载失败则降级为纯文本 VQF（仅告警，不报错）。

**运行**：多模态 serve 下用 `--image` / `--video` 传图，客户端走
`chat --image photo.jpg`（自动转 base64 data URL）。

## 5. Embedding：Qwen3-Embedding-0.6B

形态：`Qwen3ForCausalLM`（与 Qwen3-0.6B 100% 同构），但**无 `lm_head`（tied embeddings）**、
`vocab_size=151669`（奇数）。

**关键差异**：

1. **tied embeddings**：`lm_head.weight` 缺失 → 转换器 `st_load_tensor_slice("lm_head.weight")`
   失败后回退 `memcpy(token_embed)`，不报错。
2. **奇数 vocab 触发 Q4 repack 全局门**：历史上转换器对「任一矩阵几何不满足
   `vc/q_out/k_out/dim/ff`」就**全局**关闭 Q4 repack，`vocab=151669` 会写出缺
   `VQF_FLAG_Q4_4X4` 的文件被引擎拒绝。现已改为**不做全局门**，逐矩阵 `rows%4/cols%32`
   门控（与引擎一致）。
3. **取值语义**：last-token pooling + L2 归一化；配方要求编码尾部恒追加 EOS=151643
   （`tokenizer_config.json` 的 post_processor），所以 last-token 取到的是 EOS 位。

引擎侧通过 `st_embed_request()` 一次性取值钩子复用既有 prefill 内核，未登记时对 chat 路径
**零行为改变**。运行用 `--embed` / `--embed-file` / `--embed-stdin`，或 serve 下 `POST /v1/embeddings`
（务必显式 `--model-id`）。

```bash
vqf_conv --model Qwen3-Embedding-0.6B --convert-vqf qwen3-emb-0.6b/model.vqf --wmode dual
./vllm_kestrel --model qwen3-emb-0.6b --embed "hello world"
```

## 6. Laya：非自回归决策模型（ModernBERT）

形态：**双向编码器**（`is_causal=false`，无 decode 循环、无 KV cache、不生成 token），
一次前向对每个 `[MASK]` marker 打分，输出类型化决策（`choice` / `score` / `noul`）。

这不是 Qwen 系，走**独立路径**：

| 文件 | 作用 |
|---|---|
| `tools/laya_ref.py` | 先造 golden（tokenizer + DecisionModel → ids/markers/hidden/logits） |
| `tools/laya_pack.py` | 206 张量 → `laya_f16.bin` + `laya_manifest.txt`（F16 扁平 blob） |
| `tools/gen_modernbert_bin.py` | ModernBERT tokenizer.json → 引擎域 `vocab.bin` + `merges.bin` |
| `src/model/vllm_laya.c` | 权重加载 + ModernBERT 编码器前向 + 决策头 + scorer |
| `src/serve/vllm_server.c` | `POST /v1/systemone` + 懒加载 `LayaRunner` |

**与 Qwen 的关键结构差异**（任一错都致命）：

- **交替注意力**：每 3 层一个 `full_attention`，其余 `sliding_attention`（滑窗 64）。
- **双 RoPE theta**：full 层 160000 / sliding 层 10000。
- **LayerNorm**（非 RMSNorm）+ `norm_bias=false`。
- **GLU-MLP**：`erf` 精确 GELU（非 tanh 近似）。
- **层 0 `attn_norm = Identity`**（由 `embeddings.norm` 承担）。
- **决策头**：type_emb → 2×TransformerEncoderLayer(relu) → scorer。
- **温度校准**：per-(qtype, #opts) 查表，不是全局常量。

**分词器复用**：ModernBERT 也是 GPT-2 家族 byte-level BPE，直接复用引擎 BPE 引擎，
只换预分词规则（`pretoken_span_gpt2` + `qwen_tokenizer_encode_gpt2`）。

```bash
python tools/laya_pack.py <model_dir> <out_dir>
python tools/gen_modernbert_bin.py <tokenizer.json> <out_dir>
./vllm_kestrel --laya-pack <out_dir> --laya-cases <cases.txt> --laya-decide
```

## 7. YOLO：目标检测（v5 / v8 / v11）

形态：卷积网络（Conv+BN+SiLU / C2f / SPPF / Upsample / Concat / Detect head），
与 LLM 的 GEMM 主导完全不同。

**红线**：部署格式必须是引擎自有 VQF v4，**不经过 ONNX / `.rknn`**——所以要自己写
`.pt` 解析器 + 一整条卷积前向。

| 文件 | 作用 |
|---|---|
| `tools/yolo/yolo_to_vqf.py` | 用 torch/ultralytics **离线**读 `.pt` 模块图与权重，BN 折进卷积，图展平成原语算子，写 VQF v4 |
| `src/model/vllm_yolo.c` | Conv/BN/SiLU、C3/C2f/C3k2、SPPF、Concat/Upsample、Detect(DFL+anchor+NMS) |
| `src/serve/vllm_server.c` | `POST /v1/detect`（图片 base64 → 检测框 JSON） |

**版本差异**（按版分别适配，结构以解析出的 graph 为准）：

- v5：anchor-based
- v8：anchor-free + DFL
- v11：有 C2PSA 注意力

```bash
python yolo_to_vqf.py --pt yolov8n.pt --out yolov8n.vqf            # F32
python yolo_to_vqf.py --pt yolov8n.pt --out yolov8n_q8.vqf --q8   # per-channel int8
python yolo_to_vqf.py --pt yolov8n.pt --out yolov8n.vqf --check   # 转换+读回自检
./vllm_kestrel --yolo-model yolov8n.vqf --yolo-image photo.jpg
```

## 8. 分词器适配（通用）

引擎分词器 `vllm_tokenizer_qwen.c` 是 **byte-level BPE**，消费两个二进制文件：

| 文件 | 格式 | 缺失行为 |
|---|---|---|
| `vocab.bin` | `u32 vocab_size` + 每条 `{u32 tid; u16 len; bytes}` | 报错 |
| `merges.bin` | `u32 magic='QBM1'` + merges 表 + added_tokens 表 | 回退贪心最长前缀（伪 BPE） |

**引擎词表域**（重复强调）：`vocab.bin` 存原始字节，仅 `<=0x20` 字节做 GPT-2 转义，
CJK 等多字节原样。生成 merges 时必须把标准 repr 域转到引擎域再落盘（`to_engine()`）。

**同族模型复用红利**：BPE 引擎与预分词规则解耦后，第二个 GPT-2 家族模型（ModernBERT）
只换预分词正则 + 重生成 `vocab.bin`/`merges.bin`，C 侧 BPE 引擎零改动。

> 注意：`merges.bin` 是**每模型目录一份**的可选件，**切勿放到可执行文件同目录**——
> 引擎有 exe-dir 回退，会让所有模型误切到 BPE。

## 9. 接入新模型的 checklist

按形态走对应链路，逐条核对：

1. **确认形态**：因果解码器（走 `vqf_conv`）还是编码器/卷积/其它（走独立路径）。
2. **准备 HF 目录**：`config.json` + `*.safetensors`（或分片）+ `tokenizer.json` + `tokenizer_config.json`。
3. **生成词表**：`vocab.bin`（必需）+ `merges.bin`（强烈建议）。
4. **转换**：`vqf_conv --model <dir> --convert-vqf <out>/model.vqf --wmode dual [--stream]`。
5. **核对 config 识别**：看转换日志 `[CFG]` / `[ST] Config` / `[ST] Vision` 是否与预期一致
   （MoE 是否判中、vision 是否识别、head_dim 是否正确）。
6. **先 golden 再验证**：与 HF 官方输出做数值对拍（分词逐 id、前向 logits / 余弦 / 决策一致），
   再上板。
